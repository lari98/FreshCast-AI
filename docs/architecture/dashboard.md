# Dashboard (phase 9)

Next.js (App Router, TypeScript) static export in `apps/dashboard`.

## Data source
- Default: `public/demo/data.json`, generated by `scripts/export_demo_data.py`
  (trained model, forecasts, synthetic stock lots, v1 replenishment proposal,
  DE/EN explanations). All data is synthetic and labelled as such in the UI.
- Optional: set `NEXT_PUBLIC_API_URL` to read `GET /v1/dashboard` from the API.
  **That endpoint does not exist yet** (planned); the payload is validated at runtime.

Regenerate demo data: `python scripts/export_demo_data.py`.

## Screens
Store/product filters, forecast chart with 80 % interval (SVG + data table
alternative), order proposal with explanation and a human approval button
(demo: orders nothing), stock lots sorted by use-by date.

## Accessibility (engineering goals, not a conformance claim)
Skip link, landmarks, unique region names, keyboard-focusable scroll regions,
visible focus, 44 px targets, light/dark themes, reduced motion, chart not
colour-only (dash style, risk text + symbol), `lang` on explanation text,
axe-core test in CI. Colour contrast is not covered by the jsdom test and
needs a manual/browser check; the `<html lang>` is fixed to `de` (the UI
language switch changes visible text only).

## Language and formats
DE/EN toggle; `Intl` number and date formatting. Currency formatting helper
exists (EUR/CHF) but prices are not yet shown.

## Upload mode (phase 12)
"Eigene Daten analysieren" posts your CSV files to the local API (default
`http://localhost:8000`, override with `NEXT_PUBLIC_API_URL`) and shows the
result with a data-quality panel. See `byod.md`. The hosted preview page cannot
reach your local API; run the dashboard locally for this feature.

## Known gaps
No auth in the dashboard; approve is local state only; no real API calls yet.

## Markets and currencies
The header has a **Markt** switch (all DACH, Germany only, Austria only, Switzerland only,
Germany + Austria). *Settings* has one checkbox per market and per currency for any
other combination. A market is the country prefix of the store id (`DE-MUC-001` is
Germany). Deselected markets and currencies are hidden in every tab, including the
store list, the Approval workflow, alerts and the Savings replay, which is split by
market in `replay.json`. The choice is kept in the browser (localStorage). Uploaded
files whose store ids have no country prefix fall into "Other" and show without the switch.

## Retail chains and the market map
Every item can carry a retail chain (Handelskette). The same chain may sell in several
countries, so the chain is a second dimension next to the market, not part of it.

- Header **Handelskette** switch and *Settings* checkboxes filter every tab. Items with no
  chain (for example uploads without that column) are never hidden by the chain filter.
- **Marktkarte** tab: a chain x country matrix of the whole network with store count,
  item count and loss ratio per cell. A chain active in several countries shows one cell
  per country. Clicking a cell shows only that chain in that country; a button resets.
  It is a matrix, not a geographic map.
- **Savings** uses `segments` in `replay.json` (market x chain x policy raw sums) and
  recomputes fill rate, waste rate and profit change from the sums for the selection.
  Ratios are never stored per segment because averaging ratios would be wrong.
  The weekly and category tables still cover the whole network.
- Upload: a column `chain` (also `Handelskette`, `Kette`, `retailer`, `banner`) is read.
- The demo chains (MarktHaus, PreisPunkt, AlpenFrisch) are **fictional**. Real chains are
  not attached to synthetic numbers; see `docs/data/market-chains.md`.


## Quality pass (Nov 2026)

- **Today tab**: prioritised tasks (approvals, expiry, stock-outs, demand spikes, closures) derived in `lib/today.ts`.
- **Quick search**: command palette over tabs and items (`QuickSearch.tsx`).
- **Audit trail**: every settings and workflow change is logged with before/after values (`lib/audit.ts`, `AuditPanel`).
- **Paging**: long tables use `PagedRows`.
- **Fast mode**: `scripts/run-dashboard.ps1` serves the production export with `scripts/static-server.mjs`; `-Dev` for hot reload.
- **Palette**: see `docs/quality/design-tokens.md`. Test results: `docs/quality/test-report.md`.
