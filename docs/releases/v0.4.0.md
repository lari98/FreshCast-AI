# FreshCast AI v0.4.0 (2026-11-02): Offline use and per-store forecast caching

## What is new
- **Offline dashboard (service worker):** after the first visit the dashboard opens without internet. Pages are network-first with the saved copy as fallback (also while a rebuild makes the server answer 404), build files are cache-first, demo data refreshes in the background. `version.json` is never cached, so live update keeps working. A banner shows when the browser is offline; Einstellungen has a status line and a "delete offline copy" button; the footer shows "Offline bereit".
- **Safe updates:** every build generates its own worker and cache. The new worker stores the whole shell at install (if that fails, for example offline, the old worker stays), then deletes the old cache.
- **Per-store forecast caching (optional):** `FRESHCAST_PER_STORE=1` (API: `analyze_per_store`) trains one model per store and remembers each store's forecast in memory for an hour. A re-upload that changes one store retrains only that store. A store with too little history is trained together with the other short ones instead of failing the upload.
- **Version guard:** a test checks that `VERSION`, all package manifests, the API and `freshcast.__version__` agree and that release notes exist.

## Effect (measured)
- Real Chromium, production build: reload while offline works (19 tabs, overview data present, no errors); after a new build the new worker takes over, the old cache is removed, offline still works; reset leaves 0 caches and 0 workers.
- Per-store, 3 stores x 100 SKUs, 7-day holdout with ground truth: 14.5 s when one store changed, against 33.0 s with the shared model (56 % less). Cold start is slower (37.0 s against 33.0 s).
- Accuracy cost: WAPE 0.2769 against 0.2713 (+0.0056), interval coverage 79.4 % against 82.1 % (target 80 %). Therefore **per-store stays off by default**.

## Limits
Offline needs https or localhost and a finished build (not `-Dev`). Uploads and the assistant need internet. A cache hit needs byte-identical store data; caches are per process and in memory only. Benchmark is synthetic data. Same standing limits: assumed cost shares, no third-party penetration test, watts not measured.

## Upgrade
`git pull`, then `.\scripts\run-dashboard.ps1`; open the page once online. Problems with an old copy: Einstellungen, "Offline-Kopie löschen".
