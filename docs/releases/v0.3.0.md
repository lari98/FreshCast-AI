# FreshCast AI v0.3.0 (2026-11-02): Efficiency and resilience

## What is new
- **Energy-saving mode** (Einstellungen): fewer table rows per page and an update check only every 15 minutes. Starts switched on when the browser asks for less data.
- **Cheaper network use**: Brotli and gzip copies prepared once, ETag and 304 answers, update check every 5 minutes instead of every minute, none while the tab is hidden or offline, back-off after errors; API answers are gzip-compressed.
- **Lower processor load**: upload analysis uses one thread by default (same speed, half the CPU time), an identical upload is answered from a cache, at most two analyses run at once, the run script works at below-normal priority and checks for changes every 10 s.
- **More reliable**: one failing tab no longer breaks the dashboard; damaged saved settings are ignored; API readiness probe; static-server health check and time limits.
- **Safer**: extra security headers on the static server, request limits against slow and oversized requests, analysis load gate against upload floods.

## Effect (measured, see docs/quality/efficiency.md)
- 200 requests for the main script: 1,475 ms server CPU before, 0.04 ms after.
- Unchanged reload: about 23 KB before, 0 B body after. First load 234,548 B to 217,405 B.
- Update checks: 60/h to 12/h visible, 4/h energy-saving, 0/h hidden.
- Upload analysis CPU 2.98 s to 1.45 s; repeat of the same upload 1.45 s to 0.02 s.

## Limits
Watts and temperature were not measured; PowerShell changes untested on Windows here; caches and gates are per process. Same data and cost limits as before (synthetic data, assumed 60 % / 40 % cost shares, no third-party penetration test).

## Upgrade
`git pull`, then `.\scripts\run-dashboard.ps1`. New optional settings: `FRESHCAST_THREADS`, `FRESHCAST_ANALYZE_MAX_CONCURRENT`, `FRESHCAST_ANALYZE_CACHE_ENTRIES`, `FRESHCAST_ANALYZE_CACHE_TTL_SECONDS`.
